# UniGap — Αξιοποίησε τα κενά της ημέρας 🌿

**Interactive Mockup | Πανεπιστημιακή εργασία | React + Vite + Tailwind CSS**

Το **UniGap** είναι μια εφαρμογή σχεδιασμένη για φοιτητές που έχουν ελεύθερο χρόνο ανάμεσα σε μαθήματα. Αντί να μένουν χωρίς πλάνο, μπορούν να δηλώσουν **διάθεση** (διάβασμα, καφές, χαλάρωση, φαγητό) και **budget** και να δουν προτεινόμενες μικρές δραστηριότητες που χωρούν στο διαθέσιμο κενό.

> **Πρόκειται για interactive mockup, όχι για πλήρως λειτουργική εφαρμογή.** Όλα τα μαθήματα, τα μέρη, οι χρόνοι διαδρομής, οι βαθμολογίες αντιστοίχισης και οι προτάσεις είναι ενδεικτικά δεδομένα. Δεν υπάρχει backend, πραγματικό ML, GPS, πρόσβαση σε Google Calendar/Places ή πραγματικός χάρτης.

## ▶ Γρήγορη εκτέλεση για τον καθηγητή

> **Ξεκινήστε από εδώ.** Δεν χρειάζεται λογαριασμός, API key, βάση δεδομένων ή Expo Go. Η εφαρμογή ανοίγει σε browser και περιέχει μόνο ενδεικτικά δεδομένα.

1. **Προϋπόθεση:** εγκατεστημένα Node.js και npm. Αν λείπουν, δείτε την ενότητα «[Απαιτήσεις](#απαιτήσεις)» παρακάτω. Η πρώτη εγκατάσταση πακέτων χρειάζεται internet.
2. **Αποσυμπιέστε** τον φάκελο της εργασίας. Ανοίξτε τον στο VS Code και επιλέξτε **Terminal → New Terminal**. Το terminal πρέπει να βρίσκεται στον φάκελο που περιέχει το **package.json** (όχι μέσα στο src ή σε εξωτερικό φάκελο του ZIP).
3. **Πρώτη εκτέλεση:** εκτελέστε τις παρακάτω εντολές μία-μία. Περιμένετε να ολοκληρωθεί η πρώτη πριν γράψετε τη δεύτερη:

   ```bash
   npm install
   npm run dev
   ```

4. **Ανοίξτε στον browser το Local URL που εμφανίζεται στο terminal**, συνήθως **http://localhost:5173/**. Αν εμφανιστεί άλλη θύρα, χρησιμοποιήστε εκείνη.
5. **Αφήστε το terminal ανοιχτό** όσο δοκιμάζετε την εφαρμογή. Για τερματισμό πατήστε **Ctrl + C**.

**Κάθε επόμενη φορά**, ανοίξτε terminal στον ίδιο φάκελο και τρέξτε μόνο:

```bash
npm run dev
```

**Συνηθισμένα εμπόδια:**

- **Δεν αναγνωρίζεται το npm:** εγκαταστήστε το Node.js και ξανανοίξτε το terminal / VS Code.
- **Το PowerShell αναφέρει ότι το npm.ps1 δεν επιτρέπεται:** στα Windows χρησιμοποιήστε `npm.cmd install` και `npm.cmd run dev`, χωρίς αλλαγή της πολιτικής ασφαλείας.
- **Δεν βρίσκει package.json / ENOENT:** μεταφερθείτε στον σωστό φάκελο του project.
- **Κενή σελίδα με διπλό κλικ στο index.html:** χρησιμοποιήστε το Local URL του terminal, όχι το αρχείο HTML.

**Σύντομη περιήγηση:** Αρχική → επιλογή διάθεσης και budget → Δημιουργία πλάνου → Χάρτης → Προφίλ / Light–Dark. Η [κάρτα κούρασης και οι δείκτες συνωστισμού](#προσομοίωση-προβλέψεων-ui-demo) είναι προσομοιώσεις. Από το **UniGap chat · DEMO** σε κάθε καρτέλα ανοίγει το mockup του chatbot: επιλέξτε έναν έτοιμο διάλογο και κλείστε με **×** ή **Escape**. Δεν υπάρχει πραγματική αποστολή μηνυμάτων ή σύνδεση σε AI.

## Τι περιλαμβάνει

- **Dashboard / Today's Schedule:** ενδεικτικό πρόγραμμα μαθημάτων, κενό **12:00–13:30 (90 λεπτά)**, επιλογή διάθεσης και budget.
- **Smart Recommendations:** προτεινόμενα πλάνα, ενδεικτικό Match Score, χρόνο, κόστος, βήματα δραστηριοτήτων, «Αποδοχή» και «Παράβλεψη».
- **Interactive Map:** σχηματικό υπόβαθρο χάρτη με επιλέξιμα pins, φίλτρα κατηγορίας και κάρτες κοντινών σημείων. **Δεν** αναπαριστά πραγματικές διευθύνσεις.
- **Profile & Preferences:** προτίμηση για ήσυχους χώρους, μέγιστος χρόνος περπατήματος, προσομοιωμένη επιλογή ειδοποιήσεων και **Light/Dark Mode**.
- **Chatbot UI demo:** κουμπί σε κάθε καρτέλα, έτοιμοι ενδεικτικοί διάλογοι και ανενεργή σύνταξη/αποστολή. Χωρίς backend, AI ή αποθήκευση συνομιλίας.
- **Bottom navigation** ανάμεσα στις τέσσερις καρτέλες.
- **Responsive design:** από πλάτος 900 px η εφαρμογή αξιοποιεί όλη την οθόνη του browser, με τις κάρτες σε στήλες. Σε μικρότερες οθόνες διατηρείται η υπάρχουσα διάταξη.

Οι προτιμήσεις προφίλ και το θέμα αποθηκεύονται τοπικά (`localStorage`) ώστε να διατηρούνται μετά την ανανέωση της σελίδας. Το επιλεγμένο πλάνο και οι παραβλέψεις διατηρούνται **μόνο όσο παραμένει ανοικτή η τρέχουσα σελίδα**.

### Προβολή από κινητό στον ίδιο χώρο

Ενώ τρέχει το `npm run dev`, συνδέστε κινητό και υπολογιστή στο ίδιο Wi-Fi. Το Vite με τη ρύθμιση `--host 0.0.0.0` μπορεί να εμφανίζει μια **Network** διεύθυνση (π.χ. `http://192.168.x.x:5173/`), η οποία μπορεί να ανοίξει από το κινητό. Ενδέχεται να χρειάζεται άδεια στο firewall. Διαφορετικά, χρησιμοποιήστε το [δημοσιευμένο Live Demo](#live-demo-χωρίς-εγκατάσταση). **Δεν χρησιμοποιείται Expo Go** σε αυτή την web έκδοση.

## Οδηγίες δοκιμής για τον καθηγητή

1. **Αρχική:** δείτε το επόμενο ελεύθερο κενό και το πρόγραμμα.
2. Επιλέξτε διαφορετικές **διαθέσεις** και **budget** και πατήστε **«Δημιουργία πλάνου»**.
3. **Πλάνα:** δείτε τις κάρτες με εκτιμώμενο Match Score, διάρκεια, κόστος και τις επιμέρους δραστηριότητες. Πατήστε **«Γιατί αυτό το πλάνο;»**.
4. Πατήστε **«Παράβλεψη»**: το συγκεκριμένο πλάνο αφαιρείται και η επόμενη πρόταση μετακινείται προς τα πάνω. Πατήστε **«Αρχική λίστα»** για επαναφορά.
5. Πατήστε **«Αποδοχή»**: εμφανίζεται επιβεβαίωση και σύνδεσμος προς την οθόνη χάρτη.
6. **Χάρτης:** πατήστε φίλτρα, pins και τις κάρτες σημείων. Παρατηρήστε τη μεταβολή επιλεγμένου σημείου.
7. **Προφίλ:** ενεργοποιήστε/απενεργοποιήστε το **Dark Mode** ή αλλάξτε τον μέγιστο χρόνο περπατήματος. Επιστρέψτε στις προτάσεις/χάρτη και δείτε τα αποτελέσματα.
8. Ανανεώστε τον browser: το θέμα και οι προτιμήσεις διατηρούνται τοπικά.

## Live Demo χωρίς εγκατάσταση

**Live Demo URL:** Δεν υπάρχει ακόμη δημοσιευμένο URL. Μετά το deployment, προσθέστε εδώ τον πραγματικό σύνδεσμο (π.χ. `https://το-project-σας.vercel.app`). Μην γράψετε υποθετικό URL ως ενεργό demo.

### Επιλογή Α: Vercel (συνιστάται)

1. Κάντε **push** τον κώδικα σε ένα GitHub repository (μπορεί να παραμείνει **private**).
2. Δημιουργήστε λογαριασμό / συνδεθείτε στο <https://vercel.com/>.
3. **Add New → Project → Import Git Repository** και επιλέξτε το UniGap.
4. Επιβεβαιώστε τις ρυθμίσεις:
   - **Framework:** Vite
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`
5. Πατήστε **Deploy** και περιμένετε να ολοκληρωθεί η δημοσίευση.
6. Ανοίξτε το πραγματικό `https://...vercel.app` URL, δοκιμάστε το και προσθέστε το στο README / στην παράδοση.

Η Vercel μπορεί να διαβάσει private GitHub repository μετά από σχετική εξουσιοδότηση. **Το δημοσιευμένο URL είναι δημόσια προσβάσιμο**, αν δεν ενεργοποιήσετε ειδικούς περιορισμούς πρόσβασης.

### Επιλογή Β: Netlify

1. Συνδεθείτε στο <https://app.netlify.com/>.
2. Επιλέξτε **Add new project → Import an existing project** και συνδέστε το GitHub repository.
3. Build command: `npm run build` · Publish directory: `dist`.
4. Κάντε deploy και προσθέστε το πραγματικό URL στο README.

Επίσημες οδηγίες: <https://vite.dev/guide/static-deploy>.

### Επιλογή Γ: GitHub Pages

Είναι εφικτό, αλλά όταν γίνεται deploy κάτω από διαδρομή τύπου `username.github.io/repository/` πρέπει να οριστεί η κατάλληλη τιμή `base: '/repository/'` στο `vite.config.js` και να ρυθμιστεί η διαδικασία deployment. Για το πρώτο demo, το **Vercel ή το Netlify είναι απλούστερο**.

## Πώς δουλεύουν οι προτάσεις

Το αρχείο `src/mockData.js` περιέχει **όλα** τα δεδομένα προγράμματος, διαθέσιμα μέρη, mood categories και πλάνα. Η συνάρτηση `recommendPlans()` εφαρμόζει **απλούς, προκαθορισμένους κανόνες**:

- Το πλάνο πρέπει να χωρά στο κενό των 90 λεπτών.
- Το κόστος πρέπει να ανήκει στο επιλεγμένο επίπεδο budget.
- Ο μέγιστος χρόνος περπατήματος λαμβάνεται υπόψη.
- Το εμφανιζόμενο *Match Score* προσαρμόζεται με απλές προσθαφαιρέσεις ανάλογα με διάθεση και προτίμηση για ήσυχους χώρους.
- Τα πλάνα που ο χρήστης παραβλέπει **αφαιρούνται προσωρινά** από την οθόνη προτάσεων.

**Πρόκειται για mock recommender, όχι για εκπαίδευση μοντέλου.** Η οπτική προσομοίωση της προσαρμογής δείχνει την επιθυμητή συμπεριφορά της μελλοντικής εφαρμογής.

## Μελλοντική αρχιτεκτονική

Το συγκεκριμένο παραδοτέο είναι **web mockup (React DOM + Vite)**. Στο επόμενο στάδιο, εφόσον ζητηθεί native εφαρμογή Android/iOS, προτείνεται **React Native + Expo + TypeScript**. Η λογική δεδομένων και οι αρχές σχεδίασης μπορούν να επαναχρησιμοποιηθούν, αλλά **τα web UI components και το CSS/Tailwind δεν μεταφέρονται αυτούσια** σε React Native: οι οθόνες θα χρειαστούν προσαρμογή σε native components.

Προτεινόμενη αρχιτεκτονική:

```text
UniGap mobile (React Native + Expo + TypeScript)
    ├── Google Calendar API (με OAuth/συναίνεση) → ελεύθερα χρονικά κενά
    ├── Expo Location (με άδεια) → θέση του χρήστη
    └── HTTPS requests
           ↓
Backend API (Python + FastAPI)
    ├── Places service (Google Places API) → διαθέσιμα σημεία
    ├── Recommendation engine (scikit-learn)
    │      ├── Content-Based Ranking (χαρακτηριστικά μερών + προτιμήσεις)
    │      └── Contextual Bandit (μελλοντικά, από accept/reject feedback)
    └── Supabase / PostgreSQL
           ├── χρήστες και προτιμήσεις
           ├── δραστηριότητες / καταχωρίσεις
           └── feedback και ιστορικό προτάσεων
```

### Προτεινόμενη πορεία ML

1. **Κανόνες:** αρχικά, φίλτρα βάσει χρόνου, διαδρομής, budget και διάθεσης.
2. **Συλλογή feedback με συναίνεση:** εμφάνιση πρότασης, αποδοχή/παράβλεψη, προαιρετική βαθμολογία. Χρειάζονται δεδομένα από πολλές αλληλεπιδράσεις πριν αξιολογηθεί σοβαρά μοντέλο.
3. **Content-Based Recommendation:** διανύσματα χαρακτηριστικών για κάθε δραστηριότητα και προφίλ προτιμήσεων. Εκπαίδευση / κατάταξη με Python & scikit-learn.
4. **Contextual Bandits:** πιο προχωρημένο στάδιο για εξερεύνηση νέων επιλογών με στόχο την καλύτερη μακροπρόθεσμη εξατομίκευση.
5. **API endpoint (ενδεικτικό):** `POST /recommendations` με χρόνο, κατηγορία διάθεσης, budget, θέση και προτιμήσεις· επιστρέφει ταξινομημένες προτάσεις.

### Απόρρητο και λειτουργικοί περιορισμοί

- Θα απαιτούνται δικαιώματα πρόσβασης (OAuth Calendar, permission για GPS).
- Η εφαρμογή πρέπει να λειτουργεί και χωρίς αυτά, με χειροκίνητη επιλογή διαθέσιμου χρόνου/περιοχής.
- Τα Google APIs έχουν περιορισμούς, πιθανές χρεώσεις και χρειάζονται προστασία API keys.
- Να αποθηκεύονται μόνο τα αναγκαία δεδομένα με δυνατότητα διαγραφής τους από τον χρήστη.

## Προσομοίωση προβλέψεων (UI demo)

Η αρχική δείχνει ενδεικτική κούραση για το κενό 12:00–13:30, με επεξήγηση. Στον χάρτη και στα πλάνα εμφανίζεται συνεπής, ενδεικτικός συνωστισμός ανά χώρο. Οι τιμές βρίσκονται στο `src/predictionDemo.js` και είναι σταθερά δεδομένα παρουσίασης: δεν υπάρχει inference, πραγματική μέτρηση κούρασης ή σύνδεση με ζωντανά δεδομένα. Δεν επηρεάζουν την υπάρχουσα κατάταξη των προτάσεων. Το πραγματικό μοντέλο θα συνδεθεί σε επόμενο στάδιο.
